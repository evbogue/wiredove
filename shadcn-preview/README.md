# Wiredove shadcn/ui preview

This standalone Vite entry point runs alongside Wiredove's website and embeds. Both views use React components installed from the official shadcn/ui registry with the Radix Nova preset. The components live in `src/components/ui` and are imported directly by the preview.

## Run locally

Start Wiredove from the repository root:

```sh
npm ci
HOST=127.0.0.1 npm start
```

Start the preview from a second terminal in the repository root:

```sh
npm --prefix shadcn-preview ci
npm --prefix shadcn-preview run dev -- --strictPort --port 5173
```

Open http://localhost:5173/. The preview proxies API requests to `http://127.0.0.1:8000`. Set `WIREDOVE_PREVIEW_BACKEND` when starting Vite to use another Wiredove origin.

- **Social** starts with up to 50 recent verified posts, then shows older posts in batches of 25 and can publish signed text and media posts in local archive mode. The paperclip attaches PNG, JPEG, GIF, or WebP images and one audio or video file to new posts and replies. Supported video containers are MP4, WebM, and Ogg. The prototype verifies AndFS bytes before playback. Read-only share pages use a native players for locally available audio and video. Attachments are written to browser APDS through the AndFS adapter before the signed post enters the local outbox. Retry delivery resumes missing uploads to the configured server before sending the exact signed post. Viewed media and the verified feed checkpoint are cached in the browser. The preview uses the same pinned APDS module as Wiredove and requires choosing a public key before publishing. Confirmed publication shows a short toast with a link to the post. Failed deliveries stay beside the composer with Retry delivery and survive reload in the signed outbox.
- New posts, replies, public messages and edits go through **Preview** before **Publish**. **Back to editing** keeps the current text and attachments.
- Photos use a single tile or a two-column grid of square tiles. A single portrait photo is cropped to a square in the card. Galleries with more than four photos show the remaining count on the fourth tile. Open a tile to browse the full images. Composer previews use the same layout.
- Reply, public-message and edit drafts save in this browser for the current identity and target. Reopen the same composer after closing it or reloading to restore its text and any reply attachments. The **Discard draft** trash icon removes it. Sending clears the draft once the signed publication has been saved.
- **Git activity** appears in Social when an ANBot Git gateway is configured. A signed repository card opens the repo by its record hash. Initial publication and push cards also link to the exact revision. The preview reads the Git record stream and verifies the pusher's signed announcement inside each push receipt. Revision cards show up to three commit subjects at first, each with a link to the exact commit. Expand the list for the rest of the signed receipt, which contains up to 20 commits. The commit link opens inline file diffs. For a multi-commit push, **Compare push** in the card menu compares the exact before and after commits when both updates are available. The repository card shows the branch tracked by the publication.
- Older posts in the feed and author views load as you approach the last card. **Load more posts** also works with the keyboard. When you're reading farther down the feed, newer arrivals wait behind **Show new posts**.
- **Message cards** use Wiredove’s shared Markdown renderer for formatted text and links. The app gallery and public share pages recognize the same signed AndFS image references in Markdown and show alt text when an image is unavailable. Cards offer replies, thread and author views, shareable links, author-owned edits, edit history, and **Signature and data**. That dialog shows the verified author key and content ID, with one optional explanation of how verification works across servers and peers. Hide, mute, and block apply to this browser’s preview. These controls are reversible and leave the archive intact. Author and message links use a bare `#<id>` like Wiredove. The preview uses verified archive records and the current identity to resolve the destination. With `WIREDOVE_PREVIEW_SHARE_BACKEND` configured, the Share dialog and Share profile issue short public links from that server. The [runtime guide](../docs/RUNTIME_OPERATIONS.md#enable-public-share-pages) covers setup and alias storage.
- **Workspace** uses the same feed and adds a sidebar and a repository page with files, paged history, branches and tags, commit details, per-file diffs, and comparisons. Files and diffs scroll within the page. File links and **Copy commit link** pin the exact revision. **Refresh** reads the current publication on an unpinned page. **Discuss this commit** appends the pinned link to the existing Social draft and focuses the composer when publishing is enabled. On phones, use the left header button to open the sidebar as a drawer. Start Wiredove with `WORKSPACE_GIT_UPSTREAM` pointing to an ANBot instance with a selected repository to try the file tree and text previews.
- **Peers** opens from the header in either layout. It shows WebSocket relay URLs and connection status, plus the IDs of peers currently connected in the Trystero room. Add relay addresses and connect or disconnect them individually. Join or leave the room and pause or resume sync with a connected peer. The preview connects to `wss://pub.wiredove.net/` and joins the Trystero room by default. It remembers if you disconnect the default relay or leave the room. Added relay addresses are saved in the browser and connect on request.
- **Peer lookup** starts when you open a bare `#<hash>` that is missing from the feed. The existing Wiredove queue prioritizes the selected record, its signed content, and its immediate parent. Visible legacy APDS images use the normal lane. Author history follows up to 32 `previous` links per discovered head at low priority. The preview checks signature and content hashes before indexing a record and caches verified records for reopening offline. Use **Retry lookup** after an unanswered request.
- **Peer media** checks the browser cache and fetches verified AndFS blocks from the signed media origin, enabled relays that serve AndFS blocks over HTTP, or a Trystero peer running the same block exchange. Origin-free references also try Wiredove’s public media store. For historical APDS photos, the preview requests the hash from peers and also checks enabled relays over HTTP. It verifies the original data URL before caching it. Historical anblob media uses the existing HTTP reader. Replication depends on which records and blocks the peers hold. A thread can discover newer replies through announcements and archive polling.
- The **Workspace** switch in the header changes the layout without navigating away from the current page.
- **Identity setup** starts from the key icon or the composer before the first publication. Generate or regenerate a candidate, or search for a case-sensitive, two-character Base64 prefix. **Use this key** saves the keypair in the preview’s browser storage, opens the new public profile, and opens its editor. **Restore backup** opens a returning user’s profile directly.
- **Profile** opens from the avatar and shortened key in Social or the Workspace sidebar. On your own page, the pencil opens a popover for display name, bio, links, photo, and key backups. Closing the popover keeps unsaved edits in memory for that profile until you save, cancel, or reload. Saving publishes a signed profile update. Photo edits retain the original and crop. A private backup can be downloaded or restored under **Public key and backups**. Restore validates the file and requires pending signed deliveries to be retried first.
- **Settings** opens from the header gear. It controls light and dark mode and can delete the preview’s local browser data after confirmation. Download a backup from your profile editor first if you want to keep your identity.
- To let visitors browse a hosted feed before choosing a key, set `WIREDOVE_PREVIEW_FEED_BACKEND=https://bot.anproto.com` when starting Vite, or put it in the preview’s ignored `.env.local`. The browser verifies records and polls through a GET-only proxy while the tab is visible. Saving or restoring a key switches both views to the writable backend, which defaults to the local Wiredove archive. Already-saved identities open in writable mode. The **Write a post…** composer is at the top of **Feed**.
- Video posts include a **Direct video link** to `/media/<manifestHash>` on the media source. In Vite, the writable backend serves uploads and has priority for media reads, with the hosted feed backend available as a fallback. The source must have the media blocks to serve the file. A standalone same-origin `blob:` URL or Markdown image can display while the creating browser keeps that URL alive.
- Set `VITE_WIREDOVE_HOSTED=1` when running or building the preview to use the ANBot-backed feed and publishing routes of a Wiredove gateway. Use a disposable local gateway for publishing tests. The origin selected for the preview keeps its own browser storage.

Run `npm --prefix shadcn-preview run build` with the same feed settings to bundle the preview and `npm --prefix shadcn-preview run preview` to serve that bundle with the same API proxy.
